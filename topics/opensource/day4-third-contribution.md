## THE TASK

Same as before: find one genuinely approachable open issue (or
propose a small fix yourself in a project you already use) and either
open a PR or leave a thoughtful, scoped-out comment. A different
repo/language than your first two reps if you can -- variety is more
signal to employers than three reps in the same codebase.

## HOW TO EVALUATE A CANDIDATE ISSUE (checklist)

- [ ] Repo has recent commits (not abandoned)
- [ ] Issue isn't already claimed/assigned or half-solved in a stale open PR
- [ ] You can explain the ask in one sentence after reading it
- [ ] There's a CONTRIBUTING.md (or obvious PR pattern from recent merged PRs) you can follow
